# Interactive Dashboard — Design Spec

**Date:** 2026-07-22
**Status:** Approved
**Parent Spec:** `2026-07-08-harness-benchmark-design.md`

## Overview

Replace the current single-file HTML leaderboard with a modern, interactive React dashboard. Built with Vite + React + TypeScript + Tailwind + Shadcn UI + Recharts + TanStack Table. Deployed to GitHub Pages via GitHub Actions.

## Tech Stack

- **Framework:** Vite + React 18 + TypeScript
- **Styling:** Tailwind CSS (dark theme default, `#0a0a0a` background)
- **UI Components:** Shadcn UI (Card, Table, Dialog, Badge, Select, Tabs, Button, Tooltip, Accordion)
- **Table:** @tanstack/react-table (sorting, filtering, column visibility)
- **Charts:** Recharts (scatter plot, radar chart)
- **Icons:** lucide-react
- **Build:** `vite build` → `dist/`
- **Deploy:** GitHub Actions → GitHub Pages

## Data Schema

### Exported JSON (dashboard/data/benchmark-data.json)

```typescript
interface BenchmarkData {
  runs: TaskRun[];                     // Raw per-task data
  summaries: HarnessSummary[];         // Aggregated per-harness
  generated_at: string;                // ISO timestamp
}

interface TaskRun {
  harness: string;
  model: string;
  language: string;
  exercise: string;
  repetition: number;
  success: boolean;
  tokens_input: number;
  tokens_output: number;
  tokens_cached: number;
  llm_calls: number;
  tool_calls: number;                  // null if unmeasured
  duration_sec: number;
  system_prompt_tokens: number;
  tool_schema_tokens: number;
  prefix_stable: boolean;
  request_count: number;
}

interface HarnessSummary {
  harness: string;
  total_tasks: number;
  success_count: number;
  success_rate: number;                // 0-1
  pass_at_k: number;                   // 0-1
  avg_tokens_in: number;
  avg_tokens_out: number;
  avg_llm_calls: number;
  avg_tool_calls: number | null;       // null if unmeasured
  avg_duration: number;
  avg_system_prompt: number;
  avg_tool_schemas: number;
  avg_requests: number;
  prefix_stable_rate: number;          // 0-1
}
```

### Export Script (scripts/export-data.py)

Reads `results/store.db`, produces both `runs[]` (raw) and `summaries[]` (aggregated). Called after benchmark runs, committed to repo.

## UI Components

### 1. Header
- Project title "Harness Benchmark"
- Subtitle: "Coding Agent Harness Comparison"
- GitHub link, language filter (All/Python/JavaScript), model filter
- "Export JSON" button (downloads current filtered data)

### 2. Hero Cards (4 cards)
- 🏆 **Top Performer**: Highest success_rate harness
- ⚡ **Most Efficient**: Lowest tokens_input per successful task
- 🎯 **Most Reliable**: Highest pass@k
- 📊 **Total Benchmarks**: Total runs count

### 3. Trade-off Scatter Plot (Recharts)
- X-axis: Avg Tokens per Task
- Y-axis: Success Rate (%)
- Each point = one harness (bubble size = tool_schema_tokens)
- Tooltip: harness name + all metrics
- Pareto frontier visible

### 4. Exercise × Harness Heatmap
- Y-axis: exercises (sorted by difficulty)
- X-axis: harnesses
- Cells: PASS (green) / FAIL (red) / partial (amber for 1-2 out of 3)
- Click cell → highlight in leaderboard

### 5. Leaderboard Table (TanStack)
- Columns: Rank, Harness, Success, pass@k, Tokens In, Tokens Out, LLM Calls, Tools, Duration, Sys Prompt, Schemas, Stable
- Features: global search, column visibility toggle, multi-sort
- Color badges: Green >60%, Yellow 40-60%, Red <40%
- Row click → Detail Modal
- "Tools" column shows "-" for unmeasured (not 0)

### 6. Detail Modal
- Radar chart comparing selected harness across 6 normalized metrics:
  Success Rate, Token Efficiency, Speed, Tool Overhead, Prefix Stability, LLM Calls
- Each axis normalized 0-100 relative to best harness
- Below: raw metric values + comparison to average

### 7. Methodology (Accordion)
- "How it works" — Docker isolation, same LLM, Aider Polyglot exercises
- "Metrics explained" — success_rate, pass@k, prefix_stable, tool_schemas
- "Reproduce" — git clone, docker build, ./scripts/benchmark.sh
- "Limitations" — single model, no cost data, event format differences

## Build & Deploy

### Export Script
```bash
python3 scripts/export-data.py
# → dashboard/data/benchmark-data.json
# → git add + commit + push
```

### GitHub Actions (.github/workflows/deploy-dashboard.yml)

One-time setup: GitHub repo → Settings → Pages → Source = "GitHub Actions" (not "Deploy from a branch").

```yaml
name: Deploy Dashboard
on:
  push:
    branches: [main]
    paths: ['dashboard/**', 'results/store.db']
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 22 }
      - run: cd dashboard && npm ci && npm run build
      - uses: actions/upload-pages-artifact@v3
        with: { path: dashboard/dist }
  deploy:
    needs: build
    runs-on: ubuntu-latest
    permissions:
      pages: write
      id-token: write
    environment: github-pages
    steps:
      - uses: actions/deploy-pages@v4
```

## Design Decisions

1. **Vite over Next.js**: Single-page SPA with static deploy. Vite is simpler, faster builds, no "use client" complexity. Next.js App Router is designed for SSR/multi-page — overkill for this use case.

2. **Real data over mock**: Dashboard reads from actual benchmark results, not generated mock data. The export script transforms SQLite → JSON.

3. **Both raw and aggregated data in JSON**: Raw `runs[]` enables drill-down and heatmap. Aggregated `summaries[]` enables fast leaderboard rendering without client-side computation.

4. **GitHub Actions build**: JSON data committed to repo. Actions builds Vite app on push. No local Node.js required for benchmark operators.

5. **Heatmap replaces model comparison**: We have 1 model (GLM 5.2), not multiple. Exercise × harness heatmap is more useful than a model comparison matrix.
